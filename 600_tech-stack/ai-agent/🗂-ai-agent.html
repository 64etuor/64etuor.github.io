AI Agent

AI Agent

AI Agent 폴더는 LLM 기반 에이전트를 어떻게 설계하고, 무엇으로 지식을 표상하며, 어떻게 운영하고, 어디에서 실패하는가라는 네 질문에 대한 노트들을 모아 놓은 공간이다. 시스템 도면 한 장과 실패 모드 카탈로그가 같은 위계에서 마주 보고 있을 때, 에이전트 구축은 비로소 "프롬프트 한 줄"의 사고에서 빠져나온다.

구성 개념

  • AI Agent Architecture_draft — 실제 하이브리드 모노레포에서 도출한 멀티에이전트 시스템 아키텍처 초안. 생산 수준 멀티에이전트 설계의 토대.
  • Decision OS — Mirrorless Decision OS의 프로덕션 프롬프트. 회의록을 읽어 결정·액션 DB를 인간 입력을 덮지 않고 갱신하는 상태 정합 에이전트.
  • 의사 결정 트리 아키텍트 — 1회차 토론에서 반드시 결정해야 할 질문을 표면화하는 의사결정 트리 아키텍트 에이전트 시스템 프롬프트.
  • 260314 OpenClaw MeetUp — OpenClaw 밋업 현장 스크린샷(OCI AI Agent, NanoClaw, UniBase Membase, SecondBrain). 에이전트 생태계 스냅샷.
  • GraphRAG — 코퍼스에서 엔티티 그래프를 추출하고 벡터 검색과 결합해 멀티홉 질의에 답하는 Microsoft Research 패턴. 하이브리드 검색 설계의 모범 사례.
  • 신경-기호 통합 — 신경 지각과 상징 추론을 결합해 서로의 약점을 메우는 AI 패러다임. GraphRAG·에이전트 툴링·하이브리드 AI의 상위 개념 축.
  • 그라운딩 — 스키마·KB·검색 문서 같은 외부 검증 가능한 구조에 LLM 출력을 묶어 환각을 줄이는 원리. 추출·RAG·제약된 생성 설계의 토대.
  • 분산 표상 — 의미를 실수 벡터의 여러 차원에 분산해 담는 표상 패러다임. 상징적 표상 vs 신경적 표상을 비교할 때의 기준점.
  • 검증가능성 — AI 출력의 유도 과정이 입력과 규칙으로 역추적 가능하다는 속성. 감사·신뢰·규제 준수 논의의 기축.
  • LLM Wiki — Karpathy의 LLM-운영 개인 위키 패턴(raw → wiki → schema 3계층, ingest/query/lint 운영). 본 볼트 설계의 사양 출처.
  • Obsidian Vault를 Claude Code의 온디맨드 스킬 라이브러리로 활용하기 — description 중심 메타데이터와 라우팅 테이블로 Obsidian 볼트를 Claude Code 스킬 라이브러리로 구조화하는 방법론.
  • llmwiki와 본 볼트 - 무엇을 줄일 것인가 — Karpathy의 llmwiki 최소 사양과 본 볼트를 비교한 진단 글. 어떤 누적된 규칙을 줄여 compounding loop을 회복할지를 다룬다.
  • llmwiki의 두 형태 — 카파시의 최소주의에서 강제 시스템으로 — Karpathy의 최소주의 llmwiki와 본 볼트의 강제형 확장을 개념적으로 비교. 구조적 최소주의만으로는 장기 운영이 어려운 이유.
  • 스킬 구조 — Claude Code 스킬 아키텍처에 대한 스크린샷 자리(이미지 placeholder). 추후 자기 언어 노트로 확장 대기.
  • Governance and Tech Debt Review — 멀티에이전트 시스템의 8개 거버넌스 갭을 진단하고 3-트랙 리뷰 모델과 6개 운영 메커니즘을 제안. 에이전트 운영 거버넌스 설계.
  • Schema 비대화 — SSOT 문서가 규칙을 누적하며 미니멀리즘을 잃는 실패 모드. 강제 이득과 스키마 성장의 트레이드오프 판단 기준.
  • 사문화 드리프트 — 구조적으로 유효한 노트가 읽히지 않고 누적되며 잘 정리된 무덤이 되는 시스템 수준의 부패. 텔레메트리 한계와 트리아지 cadence 논의.
  • 행동적 부패 — 형식은 살아 있고 의미는 죽은 상태 — 완벽히 구조화된 노트를 아무도 읽지 않는 상황. 정적 lint 너머의 지식베이스 건강 지표 설계.
  • AI 에이전트 시대의 도래와 일하는 방식의 근본적 변화 — Karpathy의 AI 정신증·토큰 처리량 병목·에이전트 위임 패러다임 분석. 지식 노동 변화의 프레이밍.
  • The Most Important Ideas in AI Right Now (April 2026) — Daniel Miessler의 5대 핵심 아이디어(ACO, Intent-Based Engineering, Most Work is Scaffolding 등). 시대 맥락 진입점.

어떻게 포괄하는가

AI Agent 폴더의 노트들은 네 축을 따라 LLM 에이전트를 실전에 세우는 데 필요한 전체 지형을 구성한다. 첫째, 에이전트 시스템 설계 축은 "이 에이전트는 어떤 모양인가"를 다루며, AI Agent Architecture_draft가 멀티에이전트 모노레포에서 도출한 시스템 도면을 제공하고 Decision OS·의사 결정 트리 아키텍트가 두 가지 작동 패턴(상태 정합형 / 질문 표면화형)의 프로덕션 시스템 프롬프트를 노출하며 260314 OpenClaw MeetUp이 현장의 에이전트 생태계 스냅샷으로 외부 좌표를 제공한다. 둘째, 지식 표상과 검색 축은 에이전트가 무엇을 "안다"고 말할 수 있게 하는 토대이며, GraphRAG가 그래프+벡터 하이브리드 검색의 구체 패턴을 보이고 신경-기호 통합·분산 표상이 신경·기호 두 표상의 상보성과 그 형식적 차이를 정리하며 그라운딩·검증가능성이 출력의 신뢰성·추적가능성이라는 시스템 속성을 정의해 RAG·제약 생성·감사 설계의 공통 기준을 제공한다. 셋째, LLM Wiki와 Obsidian 운영 축은 에이전트가 함께 일할 지식 인프라를 설계하는 자리로, LLM Wiki가 Karpathy의 3계층 사양을 제공하고 Obsidian Vault를 Claude Code의 온디맨드 스킬 라이브러리로 활용하기가 그 사양을 description 중심 메타데이터와 라우팅 테이블이라는 구체 패턴으로 착지시키며, llmwiki와 본 볼트 - 무엇을 줄일 것인가·llmwiki의 두 형태 — 카파시의 최소주의에서 강제 시스템으로가 동일 사양을 강제형으로 확장한 본 볼트의 누적 비용을 정직하게 마주하고 스킬 구조는 그 운영을 스킬 단위로 패키징하는 잠재 표층으로 남아 있다. 넷째, 거버넌스와 실패 모드 축은 "왜 잘 만든 에이전트·잘 만든 위키도 시간이 가면 부패하는가"라는 가장 운영적인 질문을 다루며, Governance and Tech Debt Review가 8개 거버넌스 갭과 3-트랙 리뷰 모델로 조직 차원의 안전망을 그리고 Schema 비대화가 규칙 누적의 미니멀리즘 붕괴를, 사문화 드리프트가 구조적 정합은 살아 있으되 읽힘이 사라지는 표면 부패를, 행동적 부패가 정적 lint로는 결코 잡히지 않는 의미 차원의 부패를 각각의 다른 층위에서 명명한다. 이 네 축 위에 AI 에이전트 시대의 도래와 일하는 방식의 근본적 변화와 The Most Important Ideas in AI Right Now (April 2026)은 언제 왜 이 폴더가 만들어졌는가라는 시대적 좌표를 제공하는 외곽 프레임으로 자리한다 — 거버넌스·실패 모드 노트들은 이 좌표 없이 보면 추상적 우려에 가깝지만, 토큰 처리량이 곧 노동 한계가 되는 시대의 운영 비용이라는 맥락에 묶어 두면 곧장 실무 결정으로 환원된다.
