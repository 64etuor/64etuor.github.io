그라운딩

그라운딩

LLM의 자유 생성을 외부의 검증 가능한 구조 — 스키마, 지식 베이스, 검색된 문서 — 에 묶어 두는 설계 원칙. 모델이 "지어내는" 자유도를 줄이는 대신, 그 자유도를 외부 구조의 형태에 양도한다.

정의

그라운딩(Grounding)은 LLM의 출력을 모델 내부 분포 그 자체가 아니라, 외부에서 정의된 어떤 참조점 — JSON Schema, OWL 온톨로지, 데이터베이스 레코드, 검색된 문서 청크 — 에 정렬시키는 일련의 기법을 가리킨다. 핵심 가설은 단순하다. 모델이 자유롭게 생성할 때 환각하는 양은, 출력 공간이 외부 구조에 의해 좁혀질수록 줄어드는 경향이 있다. 자유도 자체가 환각의 표면적이라는 관점이다.

용어는 두 계보를 가진다. 하나는 인지과학의 symbol grounding problem (Harnad, 1990) — 기호가 어떻게 세계의 실체와 연결되는가에 대한 철학적 문제. 다른 하나는 현재 LLM 엔지니어링의 실무적 용법 — 모델 출력을 검증 가능한 무엇에 묶는 기술적 패턴. 둘은 같은 직관을 공유하지만, 후자가 다루는 것은 의미론적 connection이 아니라 형식적 constraint다. 본 노트는 후자에 집중한다.

작동 방식 — 무엇에 그라운드하는가

LLM 그라운딩은 보통 세 가지 외부 참조점 중 하나(또는 조합)에 모델을 묶는다.

그라운딩 대상 형태 대표 도구 / 패턴
스키마 (Schema) JSON Schema, Pydantic 모델, OWL 온톨로지 Instructor, Outlines, LangChain with_structured_output, OpenAI structured outputs
검색된 문서 (Retrieved context) 벡터 DB에서 가져온 청크 RAG 일반, citation-required prompting
지식 그래프 / DB Neo4j, SQL, 트리플 스토어 text2cypher, text2sql, KG-RAG

스키마 그라운딩의 메커니즘은 두 갈래로 나뉘는 경향이 있다. 소프트 그라운딩은 프롬프트에 스키마를 묘사하고 모델이 자발적으로 따르길 기대한다 — 따르지 않으면 재시도. 하드 그라운딩은 디코딩 단계에서 토큰 분포 자체를 스키마에 맞춰 마스킹한다 (Outlines의 finite-state machine 방식, llama.cpp의 grammar). 후자는 형식적으로 invalid한 출력이 발생할 확률을 0에 수렴시킨다.

부모 아티클의 맥락에서 등장하는 온톨로지 그라운딩 추출(ontology-grounded extraction) 은 첫 번째 범주의 변종이다. OWL 온톨로지나 JSON Schema 형태로 클래스·속성·관계를 사전 정의한 뒤, LLM에게 "원시 텍스트에서 이 스키마에 맞는 인스턴스만 뽑아라"고 지시하는 패턴이다. 모델은 새로운 개념을 만들지 못하고, 미리 합의된 어휘 안에서만 매핑을 수행한다.

예시

  • Instructor로 인보이스 추출: Pydantic 모델 Invoice(vendor: str, total: Decimal, line_items: list[LineItem])를 정의하고 LLM에게 PDF 텍스트를 넘기면, 라이브러리가 응답 파싱·검증·재시도를 자동 처리한다. 출력은 항상 valid Pydantic 인스턴스이거나 명시적 실패다 — 어중간한 자연어 응답이 나올 여지가 없다.
  • text2cypher: 사용자 질문 "지난달 가장 많이 팔린 카테고리는?"을 Neo4j Cypher 쿼리로 변환할 때, LLM에게 그래프 스키마(노드 레이블·관계 타입·속성)를 컨텍스트로 주입한다. 모델은 존재하지 않는 레이블을 만들어내기 어려워진다 — 출력의 정합성이 스키마 존재 자체에 의해 강제되기 때문이다.

한계 / 흔한 오해

  • 그라운딩은 환각을 줄이지 제거하지 않는다. 스키마가 valid한 출력이라도 의미론적으로 틀릴 수 있다 — total: 0.00이 형식적으로는 valid하지만 실제 인보이스 금액과 다를 수 있다. 그라운딩은 형식의 무결성을 보장하되 내용의 진실을 보장하지는 않는 경향이 있다.
  • 스키마가 너무 좁으면 모델이 표현하고 싶은 것을 잘라낸다 — "기타" 카테고리 없는 스키마는 그라운딩이 아니라 절단이 된다. 반대로 너무 넓으면 그라운딩 효과가 희석된다. 스키마 설계 자체가 정보 손실과 환각 사이의 트레이드오프다.
  • Harnad의 symbol grounding problem과 혼동하지 말 것. 그쪽은 "기호가 진짜 세계와 연결되는가"라는 철학적 질문이고, LLM 그라운딩은 "출력이 외부 구조와 형식적으로 정합한가"라는 공학적 질문이다. 같은 단어를 쓰지만 해결하려는 문제의 층위가 다르다.
