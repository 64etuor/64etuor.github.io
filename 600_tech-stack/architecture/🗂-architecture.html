Architecture

Architecture

Architecture 폴더는 객체 단위의 SOLID 규율, 시스템 단위의 신뢰성 패턴, 경계에서의 보안 방어, 그리고 그 위를 덮는 상위 아키텍처 원칙을 모아 놓은 공간이다. 한 개 객체의 책임 분할이 한 시스템의 연쇄 장애 차단과 같은 사고 형식을 공유한다는 점이 이 폴더 전체를 관통한다.

구성 개념

  • OOP 실습 - SRP 적용 예제 — SOLID 단일책임원칙을 사원-급여 예제에 Java로 구현. 책임 분할 설계의 입문.
  • OOP 실습 - OCP 원칙 예제 — SOLID 개방-폐쇄 원칙을 결제 시스템에서 인터페이스 확장 기반으로 구현.
  • OOP 실습 - 리스코프 치환 적용 예제 — SOLID 리스코프 치환 원칙을 Rectangle/Square 예제로 풀고 인터페이스 설계가 OCP까지 만족시키는 흐름을 보인다.
  • OOP 실습 - ISP 적용 예제 — SOLID 인터페이스 분리 원칙을 단일·다기능 프린터 시스템에서 구현.
  • OOP 실습 - DIP 적용 예제 — SOLID 의존관계 역전 원칙을 알림 시스템에 인터페이스 기반 DI로 구현.
  • 멱등성 - 재시도 가능한 시스템의 설계 원칙 — 분산 시스템에서 재시도를 1급 속성으로 끌어올리는 설계 원리 — 정의·메커니즘·함정·응용.
  • 회로 차단기 - 연쇄 장애를 막는 자기 보호 패턴 — 다운스트림 실패가 호출 사슬을 타고 번지지 않도록 자기 보호 본능을 시스템에 부여하는 안정성 패턴.
  • 데드락(Deadlock) - 시스템이 멈추는 네 가지 조건 — OS·DB·분산 시스템 계층에서 데드락의 원인·검출·해결 전략을 묶은 종합 정리.
  • XSS와 Injection 방어 - 시스템 경계에서 입력을 다루는 법 — XSS·SQL Injection·Command Injection이 공유하는 "데이터-코드 승격" 패턴과 바인딩·출력 인코딩·CSP의 계층 방어.
  • 클린 아키텍처(Clean Architecture) 개념 및 원칙 — Clean Architecture 개념과 의존성 규칙. Uncle Bob 계층형 아키텍처 적용·의존성 감사 시 참조.
  • Antifragile System Design 1 Optionality — 옵션성(Optionality)을 반취약 시스템의 필요조건으로 본 Taleb의 관점 — 제한된 하방, 무제한 상방, 탐색 비용 저렴.
  • SSOT가 깨지는 자리 — 데이터 아키텍처 관점 — SSOT가 깨지는 데이터 아키텍처 패턴을 다룰 자리(placeholder). 데이터 측 SSOT 분석을 시스템 아키텍처 렌즈로 다시 볼 때 확장.

어떻게 포괄하는가

Architecture 폴더의 노트들은 네 축을 따라 객체에서 시스템까지의 설계 지형을 구성한다. 첫째, SOLID 객체 규율 축은 가장 작은 단위에서 책임을 나누고 의존을 뒤집는 다섯 원칙으로 구성되며, OOP 실습 - SRP 적용 예제가 단일 책임의 입문을, OOP 실습 - OCP 원칙 예제·OOP 실습 - ISP 적용 예제가 인터페이스 확장과 분리라는 두 가지 변화 흡수 전략을, OOP 실습 - 리스코프 치환 적용 예제가 상속 계약의 행동적 일관성을, OOP 실습 - DIP 적용 예제가 의존 방향을 추상으로 향하게 뒤집어 시스템 결합을 끊는 방법을 각각 Java 코드 수준에서 정착시킨다. 둘째, 시스템 신뢰성 축은 동일한 분할·격리 사고를 시스템 단위에서 다시 적용하는 패턴들로, 멱등성 - 재시도 가능한 시스템의 설계 원칙이 재시도라는 분산 시스템의 일상 동작을 1급 속성으로 끌어올리고 회로 차단기 - 연쇄 장애를 막는 자기 보호 패턴이 다운스트림 실패를 구조적으로 차단해 폭주를 막으며, 데드락(Deadlock) - 시스템이 멈추는 네 가지 조건이 OS·DB·분산 계층을 가로지르는 정지 조건을 한 자리에서 정리해 신뢰성 분석에 공통 어휘를 제공한다. 셋째, 경계와 보안 축은 시스템 안과 바깥이 만나는 자리에서 무엇이 잘못되는가를 다루며, XSS와 Injection 방어 - 시스템 경계에서 입력을 다루는 법이 XSS·SQL Injection·Command Injection을 모두 "데이터가 코드로 승격되는 동일한 결함"으로 묶고 바인딩·출력 인코딩·CSP라는 계층 방어를 동일한 사고 틀로 통합한다 — 이 한 노트가 이 축 전체를 떠받친다. 넷째, 상위 아키텍처 원칙 축은 위 세 축을 위에서 묶는 사고 도구들로, 클린 아키텍처(Clean Architecture) 개념 및 원칙이 의존성 규칙으로 SOLID와 시스템 분할을 같은 계층 모델 위에 세우고, Antifragile System Design 1 Optionality이 시스템을 변동성을 흡수·활용하는 기계로 재정의하며 단일 패턴(회로 차단기·멱등성)을 옵션성이라는 더 큰 사고 안에 자리매김시킨다. SSOT가 깨지는 자리 — 데이터 아키텍처 관점은 이 네 축이 데이터 측에서 다시 거울에 비치는 자리로, 현재는 placeholder이지만 향후 데이터 아키텍처 SSOT 분석이 들어오면 객체-시스템-경계-원칙의 네 축에 데이터 축이 합류해 폴더 전체가 다섯 축의 균형 잡힌 카탈로그로 닫힌다.
