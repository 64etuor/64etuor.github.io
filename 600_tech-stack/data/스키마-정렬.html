스키마 정렬

스키마 정렬은 서로 다른 모델로 기술된 데이터가 같은 의미 공간에서 만나도록 개념 사이의 대응을 찾아내는 작업이다.

정의

스키마 정렬(Schema Alignment) 또는 온톨로지 매칭(Ontology Matching)은 둘 이상의 스키마·온톨로지가 가진 클래스, 속성, 관계 사이에서 의미적으로 동등하거나 포함 관계에 있는 짝을 찾아내는 절차로 볼 수 있다. 서로 다른 조직이 같은 도메인을 각자 모델링했을 때 — 의료의 SNOMED CT와 ICD, 기업의 고객 마스터 데이터와 외부 CRM, 학술 데이터셋의 메타데이터 스키마 등 — 데이터 통합은 항상 이 정렬 비용을 치른다. 학계에서는 OAEI(Ontology Alignment Evaluation Initiative)가 2004년부터 매년 매칭 시스템을 표준 벤치마크 위에서 비교해 왔으며, 이 분야의 사실상 평가 기준 역할을 한다.

구조 / 작동 방식

정렬 기법은 일반적으로 어떤 신호를 활용하느냐에 따라 네 갈래로 나뉜다.

기법 활용 신호 강점 약점
어휘 매칭 (Lexical) 레이블, 정의 텍스트, 동의어 사전 구현이 단순, 빠름 동음이의·다국어에 취약
구조 매칭 (Structural) 클래스 계층, 속성 관계 그래프 레이블이 달라도 골격이 같으면 잡힘 한쪽 그래프가 평평하면 정보 부족
인스턴스 기반 (Instance-based) 실제 데이터 분포·중복 모델보다 데이터가 풍부할 때 강력 인스턴스 누설·프라이버시 이슈
머신러닝 (ML/Embedding) 학습된 임베딩, LLM 추론 위 신호를 통합, 다국어 강건 학습 데이터 편향, 검증 어려움

실무 시스템은 보통 이 네 가지를 가중 앙상블한 뒤 사람의 검수를 마지막 단계에 둔다. 정렬 결과는 equivalent, subsumes, overlap, disjoint 같은 관계 라벨로 표현되며, 검증을 거친 매핑은 RDF의 owl:equivalentClass, SKOS의 skos:exactMatch 등 표준 어휘로 저장되는 경향이 있다.

예시

  • 의료 데이터 통합: 한 병원의 EHR이 ICD-10으로 진단을 기록하고 연구 컨소시엄은 SNOMED CT를 쓴다면, 두 코드 사이의 매핑 테이블이 곧 스키마 정렬의 산출물이다. 정렬 품질이 곧 통계적 분석의 신뢰성을 결정한다.
  • 상위 온톨로지 정렬의 절감 효과: 두 도메인 온톨로지가 처음부터 BFO나 DOLCE 같은 공통 상위 온톨로지에 정렬되어 있으면, 두 도메인 사이의 매칭은 상위 → 도메인 두 단계 매핑으로 분해되어 N×M 짝짓기 부담이 N+M으로 줄어드는 경향이 있다. 상위 온톨로지 설계 선택이 다운스트림 정렬 비용을 좌우하는 이유다.

한계 / 흔한 오해

자동 매칭은 "정답"을 주지 않는다. OAEI 벤치마크에서도 상위 시스템의 F1은 도메인과 난이도에 따라 0.5~0.9 사이를 오간다 — 정렬은 발견의 보조이지 의사결정의 대체가 아니다. 또한 두 스키마가 같은 단어를 써도 다른 개념을 가리키는 경우(가짜 친구, false friends)가 흔하므로, 자동 결과를 그대로 채택하면 통합된 데이터에 조용한 의미 오염이 누적된다.
