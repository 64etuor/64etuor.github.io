Cryptography

Cryptography

Cryptography 폴더는 패스워드 해싱·키 파생, 파일 암호화와 시크릿 관리, 통신·메시징 프로토콜의 네 축을 가로지르는 노트들을 모아 놓은 공간이다. 비밀을 어떻게 만들고 / 어떻게 운반하고 / 어떻게 저장하고 / 어떻게 갱신하는가라는 네 결정으로 보면 폴더의 흐름이 일관된다.

구성 개념

  • Argon2 — GPU·ASIC 브루트포스를 무력화하는 메모리 하드 패스워드 해싱. 세 변형(d/i/id), OWASP 권장 파라미터, Python 구현.
  • HMAC — Length Extension Attack을 방어하는 이중 해싱(ipad/opad). JWT·AWS Signature V4·TOTP 사용 사례.
  • HKDF — 하나의 공유 비밀에서 독립된 여러 키를 안전하게 파생하는 RFC 5869의 Extract·Expand 구조. TLS 1.3·Signal 활용.
  • Age — GPG 대체 파일 암호화 도구. X25519/SSH키/패스프레이즈 3 수신자 타입, HKDF 기반 내부 구조, SOPS·chezmoi 채택 사례.
  • SOPS와 Age Key — Git 저장소 안에서 시크릿을 관리하는 법 — SOPS + Age 키 조합으로 YAML/JSON 시크릿을 Git에 안전하게 커밋, chezmoi·CI/CD·dotfile까지 확장하는 DevOps 시크릿 관리.
  • Signal Protocol — Signal/WhatsApp의 X3DH 오프라인 키 교환과 Double Ratchet으로 Forward Secrecy·Post-Compromise Security를 달성.

어떻게 포괄하는가

Cryptography 폴더의 노트들은 네 축을 따라 비밀을 다루는 전체 라이프사이클을 구성한다. 첫째, 패스워드 해싱과 무결성 축은 비밀을 만드는 자리를 다루며, Argon2가 GPU·ASIC 브루트포스에 견디는 메모리 하드 해싱이라는 공격자 자원 측 비용을 인플레이트 시키는 설계를, HMAC이 메시지 변조 방어라는 다른 결의 무결성을 다뤄 — 두 노트가 같이 놓이면 "비밀을 만들기"와 "비밀로 검증하기"라는 두 자리가 한 축에 묶인다. 둘째, 키 파생 축은 하나의 비밀을 여러 비밀로 안전하게 분기하는 자리로, HKDF이 RFC 5869의 Extract·Expand 2단계로 TLS 1.3·Signal 같은 큰 시스템들이 공통으로 빌려 쓰는 파생 함수를 정리한다 — 이 한 노트가 다른 세 축이 동시에 의존하는 교차 도구다. 셋째, 파일 암호화와 시크릿 관리 축은 비밀을 어떻게 저장·운반하는가를 다루며, Age이 GPG를 대체하는 현대적 파일 암호화의 단순한 설계를, SOPS와 Age Key — Git 저장소 안에서 시크릿을 관리하는 법이 그 도구를 Git 안 시크릿이라는 운영 문제로 끌어와 — 두 노트가 암호화 라이브러리 → DevOps 실천이라는 한 결정 흐름을 채운다. 넷째, 통신·메시징 프로토콜 축은 비밀을 갱신하면서 흘려보내는 자리로, Signal Protocol이 X3DH 키 교환과 Double Ratchet으로 키가 시간 축에서 어떻게 진화하는가를 다뤄 — 이 폴더 안에서 정적 비밀(해싱·키 파생·파일 암호화)과 동적 비밀(채널을 따라 지속 갱신되는 키)을 분리해 보여 주는 유일한 노트로 자리한다. 네 축을 합쳐 보면 폴더는 HKDF이 다른 세 축이 동시에 빌려 쓰는 교차 도구 역할을 하며 비밀의 라이프사이클(생성·파생·저장·갱신)을 한 자리에서 보는 카탈로그로 닫힌다.
