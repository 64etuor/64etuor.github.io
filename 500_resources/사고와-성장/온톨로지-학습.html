온톨로지 학습

텍스트와 비정형 데이터로부터 개념·관계·공리를 자동 또는 반자동으로 추출해 온톨로지를 구축하는 과정.

정의

온톨로지 학습 (Ontology Learning) 은 도메인 전문가가 손으로 짜던 온톨로지를, 코퍼스로부터 기계가 — 또는 사람과 기계의 협업이 — 추출하도록 만드는 방법론적 흐름으로 볼 수 있다. 1990년대 말 Maedche와 Staab가 "Ontology Learning for the Semantic Web" (IEEE Intelligent Systems, 2001) 에서 학습 층위를 정리한 이후 이 개념은 자연어 처리, 정보 추출, 지식공학의 교차점에 자리잡았다. 핵심 문제의식은 단순하다 — 표상 비용 (Representation Cost) 을 낮추지 못하면 온톨로지는 결코 인터넷의 속도와 보조를 맞출 수 없다.

구조 / 작동 방식

전통적인 파이프라인은 추상의 사다리를 한 층씩 올라가는 모양을 띤다.

단계 산출물 대표 기법
1. 용어 추출 (Term Extraction) 도메인 어휘 후보 TF-IDF, C-value, 통계적 빈도
2. 개념 형성 (Concept Formation) 동의어 클러스터, 클래스 후보 분포 의미론, 클러스터링, 임베딩 유사도
3. 관계 추출 (Relation Extraction) 트리플 (subject, predicate, object) 패턴 매칭 (Hearst patterns), 의존 구문 분석, 지도학습
4. 공리 학습 (Axiom Learning) 형식 규칙, 제약 귀납 논리 프로그래밍, OWL 공리 후보 추론

LLM 시대의 변형은 이 사다리를 단축하는 경향이 있다. 거대 언어 모델이 한 번에 엔티티와 관계를 함께 추출해 그래프 인덱스로 옮기는 방식이 그것이다. Microsoft의 GraphRAG (2024) 가 채택한 그래프 인덱스 구축이 이 흐름의 산업적 사례라고 볼 수 있다 — 문서 청크에서 LLM이 엔티티와 관계를 뽑아 커뮤니티 그래프를 만들고, 그 위에서 요약과 질의가 작동한다.

예시

의료 도메인에서 SNOMED CT 같은 인간 큐레이션 온톨로지는 수십 년의 전문가 노동이 축적된 결과다. 반대로 GraphRAG의 그래프 인덱스는 같은 문서 집합에서 LLM이 몇 시간 안에 엔티티-관계 그래프를 자동 생성한다. 전자는 형식적 엄밀성과 추론 가능성이 높지만 갱신이 느리고, 후자는 빠르게 만들어지지만 추출 오류와 일관성 부족을 안고 있다.

또 다른 결은 Wikidata 같은 협업 그래프다. 사람이 트리플을 편집하지만 봇이 외부 데이터베이스와 정렬을 자동화한다 — 완전 수동도 완전 자동도 아닌, 반자동 학습의 상시 운영 사례라고 볼 수 있다.

한계 / 흔한 오해

LLM이 추출한 그래프를 "학습된 온톨로지"로 부르는 데는 주의가 필요하다. 형식 의미론적 의미에서의 온톨로지는 공리와 제약을 동반하는데, 현재 LLM 기반 추출은 대체로 트리플 수준에 머물고 공리 층까지 닿지 못하는 경향이 있다. 추출 정확도 역시 도메인에 따라 편차가 크고, 명시적 검증 없이 다운스트림 추론에 그대로 투입하면 환각이 그래프 형태로 굳어버리는 위험이 있다. "자동화되었다"는 사실이 "신뢰할 수 있다"를 자동으로 보장하지는 않는다.
