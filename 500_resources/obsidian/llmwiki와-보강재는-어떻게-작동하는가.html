llmwiki와 보강재는 어떻게 작동하는가

이 글은 노트 시스템 한 채를 분해해서, LLM이 매 턴 읽어도 비용·정확도가 무너지지 않게 만드는 구조와 그 구조를 스스로 지키는 보강재들이 어떻게 맞물려 돌아가는지를 따라간다.

목차

  • 1장. 패러다임: 노트 시스템이 아니라 LLM 위키

1장. 패러다임: 노트 시스템이 아니라 LLM 위키

1.1 두 번째 두뇌의 한계

PARA, Zettelkasten, BASB 같은 노트 시스템은 사람이 읽는다는 전제 위에 설계되어 있다. 폴더 위계, 백링크, MOC(Map of Contents)는 모두 인간의 시선·기억·습관에 맞춰져 있고, 의도된 사용자가 한 명이라는 점에서 비용 구조가 단순하다.

LLM이 매 턴 볼트를 함께 읽기 시작하면 전제가 바뀐다. 컨텍스트 한 번 채우는 데 토큰이 들고, 잘못된 라우팅 한 번은 무관한 파일 두세 개를 열게 만들며, 노트 한 곳의 표기 불일치가 다른 노트의 검색 정확도를 깎는다. 사람을 위한 노트 시스템과, LLM이 매 턴 신뢰하면서 읽는 노트 시스템은 같은 자료를 담더라도 다른 형상으로 수렴한다.

1.2 LLM 위키라는 형상

이 형상을 부르기 위한 이름이 llmwiki다. 위키피디아가 인간 군중의 편집으로 자기 정합성을 유지하듯, llmwiki는 LLM과의 매 대화가 곧 편집이고, 그 편집이 어긋나지 않게 잡아주는 결정성 검사 (Deterministic Lint) 와 행동 신호 (Read Telemetry) 두 종류의 보강재가 깔린다. 본체는 노트들이고, 보강재는 노트가 아닌 프로그램과 규칙이다. 이 글은 그 둘이 어떻게 맞물리는지 본다.

2장. 본체: 3-Layer Architecture

2.1 세 층을 다르게 로드한다

볼트가 LLM에게 자기를 설명하는 방식은 한 덩어리가 아니라 세 층으로 분리되어 있다. 모든 규칙을 하나의 CLAUDE.md에 욱여넣으면 매 턴 토큰이 새고, 반대로 모두 흩어 두면 LLM이 무엇을 읽어야 할지를 놓친다. 그래서 로드 빈도와 추상도가 다른 정보를 다른 층에 둔다.

Hub은 좁고 매 턴 로드되고 Programs는 넓고 트리거 시에만 발화한다 — 층 너비가 곧 로드 빈도다.

2.1.1 Layer 1 — Hub

AGENTS.md와 MEMORY.md가 여기에 해당한다. 매 턴 자동으로 컨텍스트에 들어오는 작은 파일이다. 담는 것은 둘 뿐이다: (1) 어떤 조건에서도 어겨선 안 되는 불변 규칙 (frontmatter 표준, 태그 형식, 파일명 금기 문자 같은 SSOT 항목), (2) 작업 유형에서 어떤 Map/Program으로 분기할지를 알려주는 라우팅 테이블.

2.1.2 Layer 2 — Maps

000_System/schema/ 아래의 tag-system.md와 vault-map.md가 Maps다. 태그 전체 카탈로그와 폴더 배치 결정 트리 — 자주 바뀌지 않지만 라우팅이 필요할 때만 펼쳐 보면 되는 참조 데이터다. Hub의 라우팅 테이블이 이 파일을 가리키고, LLM은 작업당 최대 3개까지만 가져온다.

2.1.3 Layer 3 — Programs

.claude/skills/*/SKILL.md이 Programs 층이다. 책 노트 만들기, 클리핑 가공, 질의 → 노트 저장, 볼트 lint, Related 정리 — 각각이 자기만의 트리거 키워드와 실행 단계를 갖춘 작은 워크플로우다. 키워드 매칭이 없으면 절대 호출되지 않는다.

2.2 라우팅 테이블이 인덱스다

세 층을 묶는 접착제는 AGENTS.md 안의 라우팅 테이블이다. 작업 유형 → 파일 → 한 줄 설명의 세 컬럼으로 되어 있고, LLM은 사용자의 요청을 Description 컬럼과 매칭해서 어느 Map / Program을 펼칠지 결정한다. 이 표가 비대해지지 않게 유지하는 것이 Layer 1의 핵심 위생이다 — instruction_audit.py가 90일 동안 0번 읽힌 라우팅 행을 stale 후보로 적발한다 (5장 참조).

3장. 보강재 ①: 결정성 검사 (Static Lint)

3.1 사람의 눈이 미치지 않는 일관성

본체만 두면 무엇이 망가지는가. 다섯 달 전에 정한 태그 표기가 두 달 후에 표류한다. frontmatter 한 필드가 누락된 채로 합쳐진다. wikilink가 backtick 안에 들어가서 Obsidian이 silently 끊는다. 사람이 시각으로 잡을 수 있는 양에는 한계가 있고, 잡지 못한 어긋남은 누적된다.

vault-lint.py는 사람의 시선이 닿지 않는 자리를 결정적으로 잡는 32개의 정적 검사 다. 매 vault-edit 턴의 종료 조건으로 박혀 있고, exit code가 곧 통과/실패다.

3.2 무엇을 검사하는가

검사는 카테고리별로 묶여 있다.

카테고리 대표 검사 항목
Frontmatter 정합성 7개 필수 필드, description 영문/길이, type/status 열거값, ISO 날짜
파일명 / wikilink 위생 파일명 금기 문자, backtick-감싼 wikilink, index.md 깨진 링크
태그 분류 소문자만, 2-level 한도, tag-system.md §3에서 파싱한 유효 태그
## Related 섹션 heading variant 차단, naked 항목 차단, dual section 차단
교차 참조 무결성 querySources 도착지 존재, 라우팅 backtick 경로 실존, permanent의 index.md 1-hop 도달
시간 기반 modified 드리프트, reviewed 180일 staleness (opt-in)
운영 위생 Untitled*.md 누적, index.md 노트 개수 드리프트, 시스템 파일 30KB 초과

검사 규칙의 권위는 lint 자기 자신이다. AGENTS.md의 산문은 lint이 하는 일을 설명할 뿐, 같은 규칙을 두 번 정의하지 않는다. 같은 규칙을 두 곳에 적으면 그 규칙은 즉시 두 가지 버전을 가지게 된다.

3.3 폴더별 비대칭 — 산문이 못 하는 결정

흥미로운 점은 lint이 모든 폴더에 동일한 강도로 적용되지 않는다는 점이다. 200_Books/의 한국어 책 노트, 400_Areas/의 자격증 카드, 900_Writings/의 에세이는 영문 description이나 ## Related 규칙으로부터 면제된다.

산문 규칙으로 이 정도의 면제를 적자면 매번 어긋난다. 예외 집합을 코드 상수로 못박아두는 것은, "면제를 협상하지 않는다"는 정책의 물리적 구현이다. PERSONAL_VOICE_FOLDERS, DESCRIPTION_OPTIONAL_FOLDERS, RELATED_RULES_EXEMPT_FOLDERS, TAG_FLOOR_EXEMPT_FOLDERS — 네 상수가 lint의 모든 비대칭을 정의한다.

4장. 보강재 ②: 행동 신호 (Read Telemetry & Maintenance Cadence)

4.1 lint이 보지 못하는 부패

정적 검사로는 잡히지 않는 또 다른 종류의 부패가 있다. frontmatter 7필드가 완벽하고 태그가 정확하며 모든 wikilink가 살아있는, 그러나 아무도 들여다보지 않는 노트다. 구조적으로는 건강하지만 행동적으로는 죽어 있다. 이 자리를 메우는 것이 read telemetry다.

lint은 좌측 절반(구조적 부패)을, telemetry는 하단 절반(행동적 부패)을 덮는다 — 교집합인 좌하 분면이 가장 강한 archive 신호

4.1.1 두 단계 — read_log와 dead_notes

신호는 두 단계로 만들어진다. read_log.py는 Claude Code의 transcript JSONL을 훑어 볼트 안의 파일을 대상으로 한 Read/Edit/Write/Glob/Grep 호출을 추출해 월별 TSV로 적재한다. 트랜스크립트가 SSOT이므로 멱등하다 — 다시 돌리면 같은 결과가 나온다.

dead_notes.py는 그 TSV와 vault 구조를 교차한다. N일 동안 0번 읽혔고(default 90일) 인바운드 wikilink가 0인 permanent/reference 노트만이 후보가 된다. literature, log, output, fleeting, project는 본래 한 번 쓰고 끝나는 생애를 갖기 때문에 검사 대상에서 빠진다.

4.2 cadence — 보강재 자체의 노화를 막는 보강재

보강재도 노화한다. read_log.py를 매월 돌리지 않으면 telemetry가 stale해지고, stale telemetry로 돌린 dead_notes.py는 거짓 양성을 쏟아낸다. 이 문제를 위에서 한 번 더 감싼 것이 maintenance_status.py다.

스크립트 권장 주기 무엇을 잡는가
vault-lint.py 매 vault-edit 턴 구조적 정합성 (32 검사)
read_log.py 월 1회 이상 LLM 트랜스크립트 → TSV 적재
dead_notes.py 월 1회 죽은 permanent/reference 후보
status_aging.py 분기 라이프사이클 정체 (inbox > 14d, draft > 30d 등)
graph_health.py 60일 god 노트, hub overload, echo chamber
instruction_audit.py 30일 지침 stale 후보
log_archive.py 분기 log.md 90일 초과 항목을 archive 폴더로

각 스크립트는 끝날 때 _maintenance.mark()로 자기 최종 실행 시각을 maintenance-state.json에 박는다. maintenance_status.py는 그 상태와 CADENCE_DAYS 상수를 대조해 STALE / NEVER RUN / DUE SOON / FRESH로 보고한다.

4.2.1 surface, never push — 정책으로서의 비자동화

이 모든 신호는 후보를 띄울 뿐, 자동으로 archive하지 않는다. 정책이다. dead_notes가 잡은 노트가 사실은 미래 합성을 위한 의도된 seed일 수 있고, status_aging이 잡은 draft가 일부러 묵힌 글일 수 있다. 자동화는 "올바르게 잠자는" 노트를 처벌하게 된다. 그래서 telemetry는 신호이고, 처분은 판단이다.

5장. 자기 정정 루프: SSOT와 Instruction Review

5.1 경계 규칙

지금까지의 보강재가 모두 코드라는 점은 우연이 아니다. 산문은 같은 규칙을 두 군데 적기 시작하면 곧장 두 가지 진실을 갖게 된다. 그래서 이 시스템은 같은 정보를 두 곳에 두지 않는다는 단순한 규칙 — SSOT — 을 세 가지 영역의 경계로 끌어올린다.

세 레이어, 세 계약 — 같은 정보를 두 곳에 두지 않는 것이 경계 규칙의 전부.

OMC 레이어는 agent 라우팅과 모델 선택을 담당하고, Vault 레이어는 노트 콘텐츠 규칙을 담당하며, Memory 레이어는 사용자 선호와 세션 간 지속되는 사실을 담당한다. 한 정보가 두 영역에 동시에 속하면 즉시 어느 쪽을 끄고 어느 쪽을 켤지 결정한다. 판단 기준은 "이 정보가 인간으로서 나에게 유용한가, 아니면 지식 아티팩트로서 유용한가" — 전자는 memory, 후자는 vault.

5.2 지침도 부패한다 — Instruction Review Protocol

마지막 자리는 규칙 자체의 부패다. lint이 완벽하게 enforce하기 시작한 산문 규칙은 더 이상 산문으로 존재할 이유가 없다. 폐기된 스크립트를 가리키는 라우팅 행은 무게만 차지한다. 90일 동안 한 번도 매칭되지 않은 라우팅 항목은 안 쓰이는 항목이다.

instruction_audit.py는 30일 주기로 이 패턴을 자동 적발해 instruction-review.md에 [auto] 태그로 적는다. LLM은 같은 파일에 [llm] 태그로 후보를 올릴 수 있다 — 단, "lint이 이미 끝까지 enforce한다", "여기 다른 곳에 같은 단락이 있다" 같은 구체적 증거가 있어야 한다. 막연한 직감은 노이즈가 되어 사용자가 분류해야 할 양만 늘린다. surface, never delete — 후보를 띄우는 것이 자동화의 한계이고, 삭제는 사람의 결정이다.

5.3 루프가 닫힌다

이렇게 다섯 가지가 한 고리로 닫힌다.

본체가 만들어지고, lint이 매 턴 정합성을 잡고, telemetry가 읽힘 신호로 죽은 노트를 띄우고, maintenance status가 보강재의 staleness를 감지하고, instruction audit이 지침의 부패를 적발한다. 어느 단계도 자동으로 지우지 않고, 어느 단계도 사람의 결정을 대체하지 않는다. 자동화는 신호의 정확도까지, 판단은 사람의 영역으로 — 이 분할이 시스템이 5개월간 늘어나면서도 무게를 받치는 방식이다.
