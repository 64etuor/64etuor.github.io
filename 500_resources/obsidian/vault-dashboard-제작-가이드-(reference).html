§1. 디자인 톤 선택

다루는 것: 본인이 따를 디자인 어휘 한 줄.
언제 읽나: 새 대시보드 시작 직전, 코드 한 줄 쓰기 전.
이전 절: — · 다음 절: §2

CSS 코드를 짜기 전에 어떤 톤의 대시보드를 만들 것인가를 정합니다. AI에게 디자인을 맡길 때 가장 흔한 실패는 참고 기준 없이 시작해 결국 generic SaaS Tailwind 느낌으로 수렴하는 것이라서, 출발선에 분명한 디자인 어휘를 정해 둡니다.

스킬 핵심 어휘 어울리는 대시보드
minimalist-ui (이 가이드의 예시) Notion 풍 warm monochrome, ultra-flat bento grid, 머스타드/머디 레드 액센트 매일 보는 운영 대시보드. 시각 피로 최소화 목적
industrial-brutalist-ui Swiss 타이포 + 군용 터미널, rigid grid, 극단적 타입 스케일 대비 데이터 밀도가 높거나 dramatic한 인상 필요
high-end-visual-design 에이전시 풍 premium, 정확한 그림자·간격·serif 헤딩 외부 데모용, 클라이언트 발표
advanced-visualization-techniques 인터랙티브 모션, 생성 아트, 시뮬레이션 한 페이지에 motion 강조하는 hero형 surface

스킬은 옵션 — 본인 머릿속에 이미 분명한 톤이 있다면 그 어휘로 바로 §2 CSS variable을 채우면 됩니다. 스킬은 톤이 안 잡힐 때 빌려 쓰는 외부 어휘집입니다.

스킬의 본질 — 골랐다면 금지 룰의 집합으로 이해하면 됩니다. minimalist-ui는 그라데이션·primary 컬러 배경·drop shadow를 금지하고, industrial-brutalist-ui는 둥근 모서리·파스텔을 금지합니다. 어떤 시각적 유혹을 미리 끊을지를 정하는 행위에 가깝습니다.

실행 — 스킬을 골랐을 때만 적용. SKILL.md 전체 통독 대신 핵심 토큰(컬러·폰트·border·radius·shadow)만 메모해 CSS variable로 정의하면 끝.

§3. Live counter (첫 컴포넌트)

다루는 것: dv.pages 한 줄로 동작하는 카운터 카드 4개.
언제 읽나: 가장 가벼운 대시보드를 띄우고 싶을 때, 또는 §7의 Cache 컴포넌트로 가기 전 베이스라인.
전제 조건: §1, §2 완료.
확장: §4에서 Cache 모드로 갈지 결정.

컴포넌트 시그니처 — dv.pages('"폴더"') → 상태별 카운트 → DOM 4 cards.

const notes = dv.pages('"500_Resources"');

const cards = [
	{ value: notes.length,                                   label: "total"  },
	{ value: notes.where(p => p.status === "draft").length,  label: "draft"  },
	{ value: notes.where(p => p.status === "review").length, label: "review" },
	{ value: notes.where(p => p.status === "active").length, label: "active" },
];

const grid = document.createElement("div");
grid.className = "vd-hero-grid";
cards.forEach(c => {
	const card = document.createElement("div");
	card.className = "vd-hero-card";
	const v = document.createElement("div"); v.className = "vd-hero-value"; v.textContent = c.value;
	const l = document.createElement("div"); l.className = "vd-hero-label"; l.textContent = c.label;
	card.appendChild(v); card.appendChild(l);
	grid.appendChild(card);
});
dv.container.appendChild(grid);

.vd-hero-grid {
	display: grid;
	grid-template-columns: repeat(4, 1fr);
	gap: 0;
	border: 1px solid var(--vd-border);
	border-radius: 8px;
	overflow: hidden;
}
.vd-hero-card { padding: 1.1rem 1rem; text-align: center; border-right: 1px solid var(--vd-border); }
.vd-hero-card:last-child { border-right: none; }
.vd-hero-value { font-size: 1.4rem; font-weight: 600; color: var(--vd-text); }
.vd-hero-label { font-size: 0.72rem; color: var(--vd-text-muted); text-transform: uppercase; letter-spacing: 0.05em; }

디자인 결정 — gap: 0 + border-right. 카드 사이에 공백이 없기 때문에 미세한 색차도 경계로 인식되며, 이 boundary 패턴은 §7.2에서 상태별 색을 입힐 때 다시 살아납니다.

갱신 동작 — 라이브 쿼리는 노트를 다시 열 때마다 인덱스를 새로 훑습니다. 노트 한 장 추가 시 다음 reopen에 즉시 반영. 자동 새로고침은 외부 plugin 필요.

§4. Live vs Cache 결정

다루는 것: 라이브 모드로 충분한지, 캐시 모드로 갈지의 결정.
언제 읽나: §3까지 띄운 직후, 또는 새 시그널을 얹으려는데 계산이 무거워 보일 때.
이전 절: §3 · 다음 절(Cache 시): §5

이 볼트 사례: health·knowledge는 Cache, 독서 대시보드는 Live.

Live는 가벼운 쿼리·즉시 반영일 때, Cache는 무거운 계산·주기 갱신일 때.

축 캐시 쪽으로 기우는 신호 라이브 쪽으로 기우는 신호
데이터 크기 노트 1k+, cross-note 집계 무거움 수백 노트 이내, 단순 필터
외부 도구 의존 Python으로만 가능한 lint·정규식·그래프 분석 Dataview 쿼리로 표현 가능
갱신 빈도 하루 한 번이면 충분 추가 즉시 보고 싶음
룰·임계치 변화 자주 — Python 한 곳에서 관리하고 싶음 거의 안 변함

Live 모드 정의 — 별도 cron이나 JSON 없이 dv.pages('#src/book') 같은 라이브 쿼리만으로 동작. 200권 미만 규모에선 매 reopen 100ms 이내.

Cache 모드 정의 — 캐시 빌더 스크립트가 무거운 계산을 미리 해 단일 JSON으로 저장하고, OS 스케줄러가 정기 호출. DataviewJS는 JSON 읽기만. 자동 새로고침은 의도적으로 두지 않음 — 부하 누적 위험. 인터페이스는 JSON 파일 약속 하나, 스크립트 언어·스케줄러는 자유롭게 선택.

이 vault 사례 — Python vault_dashboard.py → audits/dashboard-metrics.json. Windows Task Scheduler가 매주 월요일 06:00 run_due_maintenance.py 디스패처 호출. 스크립트는 stdlib만 사용 → 별도 패키지 설치 없음. 같은 자리에 Node·Bash·Go도 가능하고, 스케줄러도 cron·launchd·systemd timer·GitHub Actions schedule 등으로 대체 가능.

단축 룰 — 무거운 계산이 있을 때만 캐시 레이어를 추가. 라이브로 충분하면 여기서 마감.

이하 §5–§9는 Cache 모드를 골랐을 때만 필요합니다. Live면 §10 Decision Index만 훑고 끝내도 됩니다.

§5. 세 레이어 구조

다루는 것: 데이터·스타일·렌더의 분리 정신 모델.
언제 읽나: Cache 모드 시작 전 / 디자인 변경이 거대 작업으로 번질까 봐 걱정될 때.
다음 절: §6 (스타일 레이어 상세)

문제 — dv.table() 한 줄로 끝나는 99% 패턴은 두 한계에서 무너집니다 — 렌더 가능성 (표만으로는 도넛·게이지·히트맵 못 그림) + 계산 비용 (lint 풀스캔이 1–2초 멈춤).

해법 — 세 레이어 분리:

세 레이어는 각자 다른 주기로 살고, 오직 두 개의 인터페이스(JSON 파일, cssclasses)로만 접촉.

레이어 산물 (인터페이스) 갱신 주기 책임 이 vault 사례
데이터 캐시 빌더 → 단일 JSON 외부 스케줄러 무거운 계산 미리 굳힘 Python vault_dashboard.py → audits/dashboard-metrics.json, Windows Task Scheduler 주 1회
스타일 CSS snippet 디자인 변경 시 시각 토큰 정의 .obsidian/snippets/VaultDashboard.css
렌더 대시보드 노트의 DataviewJS 블록 매 reopen 시 JSON 읽고 DOM 000_System/dashboards/health.md, knowledge.md

얻는 것 (3개) — (1) 노트 reopen 시 무거운 계산 안 함, (2) 다크모드 분기 한 블록으로 전체 톤 바뀜, (3) 한 레이어 갈아엎어도 나머지 둘 생존 (예: 캐시 빌더를 Python → Node로 옮겨도 CSS·DataviewJS 무변경).

§7.1 평가 배너

6개 시그널을 임계치로 분류해 가장 나쁜 상태로 배너의 색이 결정. "지금 무엇이 문제인가"를 한 시선에 전달.

const file = await dv.io.load("000_System/audits/dashboard-metrics.json");
const m = JSON.parse(file);

const classify = (signal, v) => {
	const cfg = m.thresholds[signal];
	if (!cfg) return "clean";
	if (v >= cfg.alarm) return "alarm";
	if (v >= cfg.warn)  return "warn";
	return "clean";
};

const verdicts = [
	classify("lint_must",      m.lint.must_total),
	classify("lint_soft",      m.lint.soft_total),
	classify("dead_notes",     m.behavioral.dead_notes),
	classify("status_stuck",   m.behavioral.status_aging),
	classify("god_notes",      m.behavioral.god_notes),
	classify("echo_chambers",  m.behavioral.echo_chambers),
];
const alarm = verdicts.filter(v => v === "alarm").length;
const warn  = verdicts.filter(v => v === "warn").length;

const banner = document.createElement("div");
banner.className = "vd-banner " + (alarm ? "alarm" : warn ? "warn" : "clean");
banner.textContent = alarm
	? `${alarm} signal(s) over alarm`
	: warn ? `${warn} signal(s) over warn` : "all signals clean";
dv.container.appendChild(banner);

.vd-banner { padding: 0.85rem 1.25rem; border: 1px solid var(--vd-border); border-radius: 8px; }
.vd-banner.alarm { border-color: var(--vd-alarm-border); background: var(--vd-alarm-bg); color: var(--vd-alarm-text); }

핵심 사실 — 임계치는 코드가 아니라 JSON(m.thresholds)에 삽니다. 임계치를 조정할 때 DataviewJS 블록을 안 건드리고 Python 한 곳에서 끝납니다. 모든 컴포넌트가 같은 thresholds를 공유.

§7.3 Maintenance 진행바 — chart 아닌 신호

진행 바는 4px 두께. 더 굵으면 chart처럼 보이고 정보 위계가 깨짐. 원칙: 차트는 본문 주인공일 때만 굵게, 사이드 신호는 슬쩍 끼어드는 두께.

const now = Date.now();
const rows = Object.entries(cadences).map(([name, cadence]) => {
	const last = state[name];
	const ageDays = last ? Math.floor((now - new Date(last).getTime()) / 86400000) : null;
	const status =
		ageDays == null         ? "never" :
		ageDays > cadence       ? "stale" :
		ageDays > cadence*0.75  ? "due"   : "fresh";
	return { name, ageDays, cadence, status };
});

const grid = document.createElement("div");

rows.forEach(r => {

	card.appendChild(bar);
	grid.appendChild(card);
});

§7.6 Donut chart — vanilla SVG 30줄

차트 라이브러리 안 쓴 이유 두 가지 — (1) DataviewJS의 모듈 import 제약, (2) 라이브러리 기본 톤 override 작업이 새로 그리는 것보다 귀찮음.

const PALETTE = ["#2F3437","#4a4f53","#6b7075","#8a8f93","#a8acb0","#c2c6c9"];
const size = 100, stroke = 14, r = (size - stroke) / 2, c = 2 * Math.PI * r;

let acc = 0;
data.forEach(([_, v], i) => {
	const dash = (v / total) * c;
	const seg = document.createElementNS("http://www.w3.org/2000/svg", "circle");
	seg.setAttribute("r", r);
	seg.setAttribute("fill", "none");
	seg.setAttribute("stroke", PALETTE[i % PALETTE.length]);
	seg.setAttribute("stroke-width", stroke);
	seg.setAttribute("stroke-dasharray", `${dash} ${c - dash}`);
	seg.setAttribute("stroke-dashoffset", -acc);
	seg.setAttribute("transform", `rotate(-90 ${size/2} ${size/2})`);
	acc += dash;
	svg.appendChild(seg);
});

핵심 트릭 — stroke-dasharray + stroke-dashoffset. 호(arc)를 path로 그리는 것보다 짧음.

팔레트 결정 — #2F3437 한 hue의 명도 단계만. 카테고리 컬러(빨강·파랑·노랑) 안 씀. 정보는 legend의 숫자가 전달하고, 도넛은 비율 감각만 제공.

§7.7 Activity heatmap — 달력 산수

53주×7요일 grid를 vanilla flexbox. 색은 초록 단계 아닌 단색 opacity 5단계.

까다로운 자리 — 시각이 아니라 달력 산수. 1월 1일 요일이 매년 다르므로 첫 주 첫 열의 빈 셀 개수가 매년 바뀜. 12개 월 라벨을 53개 column에 분포시킬 때 어느 column에서 새 달이 시작하는지 정확 계산 필요.

핵심 패턴 — 헤더를 53-슬롯 grid로 만들고, 각 달이 시작하는 column에만 라벨 박음. 헤더의 column 폭과 본문 cell 폭이 12px로 동일, gap도 같음 → label과 cell이 1:1 정렬.

const YEAR = new Date().getFullYear();
const jan1 = new Date(YEAR, 0, 1);
const jan1Dow = jan1.getDay();

const monthStartWeek = {};
for (let mi = 0; mi < 12; mi++) {
	const first = new Date(YEAR, mi, 1);
	const dayOfYear = Math.round((first - jan1) / 86400000);
	monthStartWeek[Math.floor((dayOfYear + jan1Dow) / 7)] = mi;
}

const header = document.createElement("div");
header.className = "vd-heat-header";
header.appendChild(Object.assign(document.createElement("div"), { className: "vd-heat-day" }));
for (let week = 0; week < 53; week++) {
	const slot = document.createElement("div");
	slot.className = "vd-heat-month";
	if (monthStartWeek[week] !== undefined) slot.textContent = monthNames[monthStartWeek[week]];
	header.appendChild(slot);
}
container.appendChild(header);

for (let dow = 0; dow < 7; dow++) {
	const row = document.createElement("div");
	row.className = "vd-heat-row";
	const label = document.createElement("div");
	label.className = "vd-heat-day";
	label.textContent = (dow === 1 || dow === 3 || dow === 5) ? dayNames[dow] : "";
	row.appendChild(label);
	for (let week = 0; week < 53; week++) {
		const offset = week * 7 + dow - jan1Dow;
		const date = new Date(YEAR, 0, 1 + offset);
		const cell = document.createElement("div");
		cell.className = "vd-heat-cell";
		if (date.getFullYear() !== YEAR || offset < 0) cell.classList.add("empty");
		else {
			const n = counts[`${YEAR}-${String(date.getMonth()+1).padStart(2,'0')}-${String(date.getDate()).padStart(2,'0')}`] || 0;
			const cls = bucket(n);
			if (cls) cell.classList.add(cls);
			if (date > today) cell.classList.add("future");
		}
		row.appendChild(cell);
	}
	container.appendChild(row);
}

정렬 떠받치는 두 결정 — (1) .vd-heat-month와 .vd-heat-cell이 같은 폭(12px), (2) 헤더 row와 본문 row가 같은 gap(2px). out-of-year cell은 투명이 아닌 옅은 placeholder로 그려야 calendar grid가 1월~12월까지 시각적 연속.

§7.8 Triage 리스트 — 공통 컴포넌트

dead notes·broken wikilinks·status aging이 모두 같은 "후보 + 메타 + 점프" 패턴. 공통 함수로 묶어 한 곳 수정에 셋 따라옴.

const buildTriageItem = (titleText, metaText, onClick) => {
	const item = document.createElement("div");
	item.className = "vd-triage-item";
	const t = document.createElement("span");
	t.className = "vd-triage-title-text";
	t.textContent = titleText;
	const m = document.createElement("span");
	m.className = "vd-triage-meta";
	m.textContent = metaText;
	item.appendChild(t); item.appendChild(m);
	item.addEventListener("click", onClick);
	return item;
};

top.forEach(r => {
	const name = r.path.split("/").pop().replace(/\.md$/, "");
	const folder = r.path.split("/").slice(0, -1).join("/");
	list.appendChild(buildTriageItem(
		name,
		`${r.type} · ${folder || "/"}`,
		() => app.workspace.openLinkText(r.path, "/", false),
	));

openLinkText 인자 — 세 번째가 false면 현재 탭, true면 새 탭. broken wikilink는 항상 새 탭 — 아직 만들지 않은 노트라 새 작업 시작이고 새 탭이 의도와 더 맞음.

hover 정책 — background만 살짝. transform·shadow 변화 ✗ — minimalist-ui의 "hover effect는 invisible해야 한다"는 원칙.

§8. DataviewJS 공통 패턴

다루는 것: 모든 컴포넌트 위에 깔리는 안전장치 네 가지.
언제 읽나: 새 컴포넌트 추가 시 checklist로.

(1) JSON 로딩 가드는 첫 줄
const file = await dv.io.load("000_System/audits/dashboard-metrics.json");
if (!file) { dv.paragraph("_metrics json missing — `python vault_dashboard.py` 실행 필요_"); return; }
const m = JSON.parse(file);
(2) 블록당 컴포넌트 하나

한 블록 throw 시 전체 죽음. 컴포넌트 단위로 쪼개야 다른 섹션 생존.

(3) appendChild는 마지막에 한 번 — document.createElement로 만들어두고 모두 만든 뒤 dv.container.appendChild(root)로 한 번. 중간에 여러 번이면 preview rerender 시 깜빡임.

(4) dv.pages() vs app.vault.getFiles() — dv.pages()는 markdown만 인덱스. png·pdf·svg·canvas embed는 빠짐. broken wikilink 탐지에서는 false positive로 이어지므로 별도 set 만들어 비교.

const vaultFiles = new Set(app.vault.getFiles().map(f => f.path));

§9. 알려진 한계

한계 우회 비용
reopen 해야 갱신 외부 plugin (실시간) 매일 보는 맥락에선 reopen 부담 작음
JSON 없을 때 한 줄 fallback만 더 강한 에러 처리 비용 대비 가치 낮음
inline SVG 자동 재계산 ✗ ResizeObserver 별도 박기 도넛이 부모 크기와 안 맞을 때만
mobile DataviewJS DOM 조작 느림 카드 수 ≤ 6 유지 더 많으면 체감 지연
dv.io.load()는 vault-root-relative만 절대 경로·../ 안 됨 — 그냥 vault-root 기준 사용 우회 불필요

공통 패턴 한계 — 모두 렌더 레이어의 비용. 데이터·스타일 레이어는 분리 덕분에 거의 영향 없음. 다음 단계 개선이 정말 필요해진다면 — 렌더 레이어를 Obsidian 플러그인으로 옮겨 lifecycle hook을 잡는 것 — 그 시점은 매일 보는 사람이 본인 한 명이 아니게 됐을 때. 개인 vault 규모에선 현재 패턴이 비용·효용 sweet spot.
